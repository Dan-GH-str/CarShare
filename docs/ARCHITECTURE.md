# Архитектура CarShare

## Монорепозиторий

```text
frontend/  React + Vite приложение
backend/   NestJS API
docs/      материалы для курсового проекта
```

## Backend

Backend разделен на модули:

- `auth` - регистрация, вход, refresh token, logout, текущий пользователь.
- `users` - профиль и статистика пользователя.
- `categories` - публичные категории каталога.
- `cars` - каталог, фильтры, карта, карточка автомобиля, отзывы.
- `bookings` - расчет, бронирование, старт, отмена и завершение поездки.
- `trips` - активная поездка и история пользователя.
- `receipts` - просмотр неизменяемых чеков.
- `reviews` - отзыв о сервисе.
- `admin` - dashboard, таблицы и модерация.
- `pricing` - чистая бизнес-логика расчета стоимости.
- `prisma` - PrismaClient как Nest service.

## Жизненный цикл бронирования

Бронирование разделяет удержание автомобиля и фактическую поездку:

- `RESERVED` - автомобиль закреплен за пользователем, но аренда еще не тарифицируется.
- `ACTIVE` - пользователь нажал "Начать поездку", зафиксирован `actualStartAt`, началась тарификация аренды.
- `COMPLETED` - поездка завершена, сервер пересчитал стоимость и сформировал чек.
- `CANCELLED` - бронь отменена до старта; сервер фиксирует бесплатную отмену или удержание.
- `EXPIRED` - пользователь не начал поездку до `expiresAt`, автомобиль возвращается в каталог.

`startAt` задает плановый старт. Для бронирования "сейчас" это момент создания брони, для отложенного старта - выбранная пользователем дата и время. Поездку можно начать только в разрешенном окне: не раньше чем за 10 минут до `startAt` и не позже `expiresAt`.

После `startAt` действует 15 минут бесплатного ожидания. Если пользователь не стартовал, сервер начисляет платное удержание автомобиля до старта или до истечения брони. Платное ожидание хранится отдельно от обычных дополнительных опций и попадает в чек отдельной строкой.

Отмена до старта считается отдельным сценарием жизненного цикла. Первые 5 минут после создания брони и отмена раньше чем за 30 минут до `startAt` бесплатны. Поздняя отмена до `startAt` удерживает фиксированный сбор, а отмена после `startAt` удерживает только платное ожидание после бесплатного окна.

## Данные

Prisma schema описывает пользователей, сессии refresh token, категории, модели, автомобили, тарифы, опции, бронирования, чеки и отзывы. Данные пользователя хранят фамилию, имя и отчество отдельными полями, без общего поля для полного имени.

Чек хранит snapshot автомобиля, пользователя, тарифа и строк начислений. Поэтому изменение тарифа или профиля после поездки, платной отмены или no-show не меняет уже сформированный чек.

## Frontend

Frontend построен mobile-first:

- нижняя навигация для основных разделов;
- каталог с горизонтальными категориями и листом фильтров;
- переключение списка и карты на Яндекс.Картах JS API с резервной схемой;
- sticky-блок бронирования на широких экранах;
- плотная CRUD-админка без отдельного декоративного лендинга.

API-запросы идут через единый клиент `src/api/client.ts`. Access token хранится в `localStorage`, при `401` клиент пытается обновить сессию через refresh token и повторить запрос.
