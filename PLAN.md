# CarShare: план проектирования веб-системы каршеринга

## 1. Назначение системы

CarShare - информационная веб-система каршеринга с пользовательским и административным интерфейсами.

Система позволяет пользователям находить доступные автомобили, фильтровать их по категории и характеристикам, просматривать машины на карте или в списке, бронировать автомобиль на часы, сутки или длительный период, выбирать дополнительные опции, завершать поездки, получать чек и оставлять отзывы.

Администратор управляет автопарком, категориями, моделями, тарифами, дополнительными опциями, пользователями, бронированиями и отзывами.

Проект реализуется как учебное веб-приложение без настоящего платежного шлюза: стоимость поездки рассчитывается сервером, а чек формируется и сохраняется после завершения поездки.

## 2. Технологический стек

### Frontend

- React + TypeScript + Vite.
- React Router для маршрутизации.
- TanStack Query или RTK Query для загрузки, кеширования и обновления данных API.
- React Hook Form + Zod для форм и валидации.
- Яндекс.Карты JS API для карты доступных автомобилей; при отсутствии ключа используется встроенная схема расположения.
- CSS Modules, SCSS или Tailwind CSS для стилизации.

### Backend

- NestJS + TypeScript.
- Prisma ORM.
- PostgreSQL.
- JWT access token + refresh token/session flow.
- Docker Compose для локальной базы данных.
- Swagger/OpenAPI для документации API.

### Инфраструктура проекта

Рекомендуемая структура монорепозитория:

```text
CarShare/
  frontend/              React-приложение
  backend/               NestJS API
  docs/                  дополнительные материалы курсового
  docker-compose.yml     PostgreSQL для локальной разработки
  .env.example           пример переменных окружения
  PLAN.md
  TASKS.md
```

## 3. Роли и права доступа

### Гость

- Просматривает главную страницу и публичный каталог.
- Может открыть страницу автомобиля.
- Не может бронировать, оставлять отзывы и смотреть поездки.
- При попытке бронирования перенаправляется на вход или регистрацию.

### Пользователь

- Регистрируется и входит в систему.
- Просматривает каталог в виде списка и карты.
- Фильтрует автомобили по категории, приводу, цвету, комплектации, опциям и доступности.
- Создает бронирование.
- Запускает и завершает поездку.
- Просматривает активную поездку, историю поездок и чеки.
- Оставляет отзывы на автомобили и сервис.
- Редактирует профиль.

### Администратор

- Имеет доступ к административной панели.
- Управляет пользователями, автомобилями, моделями, категориями, тарифами и опциями.
- Меняет статусы автомобилей и бронирований.
- Просматривает историю поездок и чеки.
- Модерирует отзывы.
- Видит сводные показатели системы.

### 4.5. Бронирование и активная поездка

Сценарий:

1. Пользователь выбирает автомобиль.
2. Выбирает тип тарифа: часы, сутки или длительный период.
3. Указывает период аренды или количество часов/суток.
4. Выбирает старт: сразу или на запланированное время.
5. Включает дополнительные опции.
6. Система рассчитывает предварительную стоимость на сервере.
7. Пользователь подтверждает бронирование.
8. Бронирование получает статус `RESERVED`, автомобиль закрепляется за пользователем, но аренда еще не началась.
9. При нажатии "Начать поездку" в разрешенном окне статус меняется на `ACTIVE`, фиксируется `actualStartAt`.
10. До старта пользователь может отменить бронь; сервер рассчитывает возможное удержание и освобождает автомобиль.
11. При завершении поездки статус меняется на `COMPLETED`, сервер пересчитывает стоимость и формирует чек.

Правила старта и ожидания:

- Для бронирования "сейчас" `startAt` равен моменту создания бронирования.
- Для запланированного бронирования пользователь задает `startAt` в будущем.
- Поездку можно начать не раньше чем за 10 минут до `startAt`.
- После `startAt` действует 15 минут бесплатного ожидания.
- После бесплатного ожидания начисляется платное удержание автомобиля, например 5 руб/мин.
- Если поездка не началась через 30 минут после `startAt`, бронирование получает статус `EXPIRED`, автомобиль возвращается в `AVAILABLE`.
- Тариф аренды считается с `actualStartAt`, а не с момента бронирования.
- Итоговый чек включает аренду, дополнительные опции и начисленное платное ожидание.

Правила отмены до старта:

- В течение 5 минут после создания бронирования отмена бесплатна.
- Если до `startAt` больше 30 минут, отмена также бесплатна.
- Если до `startAt` меньше 30 минут, но поездка еще не началась, удерживается фиксированный сбор поздней отмены: 100 руб.
- Если `startAt` уже наступил, но пользователь не нажал "Начать поездку", первые 15 минут ожидания бесплатны.
- После бесплатного ожидания при отмене удерживается только платное ожидание автомобиля: 5 руб/мин.
- При платной отмене или no-show создается чек со строкой удержания, а `totalAmount` отражает фактическое удержание, а не цену несостоявшейся поездки.

Активная поездка:

- Автомобиль.
- Время начала.
- Плановое время завершения.
- Прошедшее/оставшееся время.
- Текущая сумма.
- Кнопка завершения поездки.

Основано на экранах "Мои поездки" и "Чек оплаты" из PDF.

Экран "Мои поездки":

- Активная поездка.
- История завершенных поездок.
- Статус поездки.
- Даты начала и окончания.
- Длительность.
- Итоговая сумма.
- Использованные опции.
- Кнопка "Показать чек".

Чек:

- Номер чека.
- Автомобиль.
- Дата начала.
- Дата окончания.
- Длительность.
- Строки начислений: аренда, доставка, детское кресло и другие опции.
- Итоговая сумма.
- Кнопка закрытия.
- Кнопка скачивания PDF или печати через браузер.

Чек хранится как неизменяемый snapshot: последующие изменения тарифов или автомобиля не должны менять уже сформированный чек.

Разделы:

- Dashboard: количество пользователей, автомобилей, активных бронирований, завершенных поездок, выручка по чекам.
- Пользователи: список, поиск, роли, блокировка/разблокировка.

- Модели: бренд, модель, характеристики, особенности.

- Тарифы: почасовая, суточная и длительная ставки.
- Дополнительные опции: название, тип цены, стоимость, активность.
- Бронирования: список, статусы, детали, отмена.
- Отзывы: список, модерация, скрытие/публикация.

## 5. Backend-архитектура

### 5.1. NestJS-модули

- `auth` - регистрация, вход, refresh token, выход.
- `users` - профиль пользователя и управление пользователями.
- `cars` - каталог, карточка автомобиля, карта, статусы.
- `categories` - категории автомобилей.
- `models` - модели автомобилей и характеристики.
- `tariffs` - тарифы.
- `options` - дополнительные опции.
- `bookings` - бронирования, старт и завершение поездки.
- `trips` - пользовательская история поездок.
- `receipts` - чеки.
- `reviews` - отзывы на автомобили и сервис.
- `admin` - административные сводки и защищенные CRUD-сценарии.
- `prisma` - доступ к базе данных.
- `common` - guards, decorators, pipes, filters, shared DTO.

### 5.2. Основные API endpoints

Auth:

- `POST /auth/register` - регистрация.
- `POST /auth/login` - вход.
- `POST /auth/refresh` - обновление access token.
- `POST /auth/logout` - выход.
- `GET /auth/me` - текущий пользователь.

Catalog:

- `GET /categories` - список категорий.
- `GET /cars` - список автомобилей с фильтрами.
- `GET /cars/map` - автомобили для карты.
- `GET /cars/:id` - детальная карточка автомобиля.
- `GET /cars/:id/reviews` - отзывы автомобиля.

Bookings and trips:

- `POST /bookings/quote` - предварительный расчет стоимости.
- `POST /bookings` - создание бронирования.
- `GET /bookings/active` - активное бронирование пользователя.
- `POST /bookings/:id/start` - старт поездки.
- `POST /bookings/:id/finish` - завершение поездки и формирование чека.
- `POST /bookings/:id/cancel` - отмена бронирования до старта с расчетом удержаний.
- `GET /trips/my` - история поездок пользователя.

Receipts:

- `GET /receipts/:id` - просмотр чека.
- `GET /receipts/:id/download` - скачивание/печать чека в PDF в расширенной версии.

Reviews:

- `POST /cars/:id/reviews` - отзыв на автомобиль.
- `POST /service-reviews` - отзыв о сервисе.

Admin:

- `GET /admin/dashboard` - показатели системы.
- `GET/POST/PATCH/DELETE /admin/cars`.
- `GET/POST/PATCH/DELETE /admin/models`.
- `GET/POST/PATCH/DELETE /admin/categories`.
- `GET/POST/PATCH/DELETE /admin/tariffs`.
- `GET/POST/PATCH/DELETE /admin/options`.
- `GET/PATCH /admin/users`.
- `GET/PATCH /admin/bookings`.
- `GET/PATCH /admin/reviews`.

### 5.3. Realtime-каталог

Для первой версии realtime-доступность реализуется без WebSocket:

- клиент обновляет каталог и данные карты каждые 15 секунд;
- сервер всегда возвращает актуальный статус автомобиля;
- бронирование создается в транзакции;
- если автомобиль уже занят или находится на обслуживании, сервер отклоняет бронирование.

Возможное расширение:

- заменить polling на WebSocket/SSE для мгновенного обновления маркеров на карте.

## 7. Бизнес-правила

- Пользователь не может создать бронирование без авторизации.
- Заблокированный пользователь не может бронировать автомобили и оставлять отзывы.
- Нельзя бронировать автомобиль со статусом `RESERVED`, `ACTIVE`, `MAINTENANCE` или `DISABLED`.
- Нельзя создавать пересекающиеся активные бронирования на один автомобиль.
- Один пользователь может иметь только одну активную поездку одновременно.
- Один пользователь может иметь только одно незавершенное бронирование или активную поездку одновременно.
- Бронирование может быть создано на текущий момент или на запланированное время `startAt`.
- Старт поездки раньше допустимого окна блокируется сервером.
- Бронирование в статусе `RESERVED` удерживает автомобиль, но тарификация аренды начинается только после перехода в `ACTIVE`.
- Если пользователь не начал поездку в бесплатное окно ожидания, сервер начисляет платное удержание автомобиля.
- Если пользователь не начал поездку до `expiresAt`, бронирование истекает, а автомобиль снова становится доступным.
- Стоимость всегда рассчитывается на сервере, даже если клиент показывает предварительный расчет.
- При завершении поездки сервер пересчитывает итоговую сумму по фактической длительности.
- Чек формируется только для завершенной поездки.
- Чек хранит snapshot данных и не меняется при обновлении тарифов, модели или профиля пользователя.
- Отзыв на автомобиль можно оставить только после завершенной поездки на этом автомобиле.
- Администратор может менять статус автомобиля, но не должен удалять автомобиль, если по нему есть история поездок; вместо удаления используется отключение.

## 8. Расчет стоимости

### Почасовой тариф

Используется для коротких поездок.

Формула:

```text
baseAmount = округленное_количество_часов * hourlyPrice
totalAmount = baseAmount + стоимость_опций
```

Минимальная единица тарификации: 1 час в учебной версии. Если нужна поминутная точность, ее можно добавить как расширение.

### Посуточный тариф

Используется для аренды на сутки или несколько суток.

Формула:

```text
baseAmount = количество_суток * dailyPrice
totalAmount = baseAmount + стоимость_опций
```

### Длительный тариф

Используется при аренде от заданного количества дней, например от 7 суток.

Формула:

```text
baseAmount = количество_суток * longTermDailyPrice
totalAmount = baseAmount + стоимость_опций
```

### Опции

- `FIXED`: добавляется один раз.
- `PER_HOUR`: умножается на количество часов.
- `PER_DAY`: умножается на количество суток.

### Ожидание старта

Платное ожидание не является обычной доп. опцией. Оно рассчитывается сервером только для бронирований, которые не были начаты после бесплатного окна.

```text
freeWaitUntil = startAt + 15 минут
expiresAt = startAt + 30 минут
waitAmount = округленные_минуты_платного_ожидания * waitPricePerMinute
totalAmount = baseAmount + optionsAmount + waitAmount
```

Для отмененного до старта бронирования аренда не начисляется:

```text
freeCancellationUntil = createdAt + 5 минут
freeCancellationBefore = startAt - 30 минут
cancellationAmount = 0 или 100 руб. для поздней отмены до startAt
waitAmount = платное_ожидание_после_startAt
totalAmount = cancellationAmount + waitAmount
```

## 9. Состояния бронирований и автомобилей

### Booking status

- `RESERVED` - автомобиль забронирован, поездка еще не началась; действует окно старта и ожидания.
- `ACTIVE` - поездка идет, аренда считается с `actualStartAt`.
- `COMPLETED` - поездка завершена, чек сформирован.
- `CANCELLED` - пользователь или администратор отменил бронирование; возможен чек удержания.
- `EXPIRED` - бронирование истекло без старта; автомобиль освобожден, удерживается только платное ожидание.

### Car status

- `AVAILABLE` - автомобиль доступен в каталоге.
- `RESERVED` - автомобиль забронирован.
- `ACTIVE` - автомобиль используется в поездке.
- `MAINTENANCE` - автомобиль на обслуживании.
- `DISABLED` - автомобиль скрыт из пользовательского каталога.
